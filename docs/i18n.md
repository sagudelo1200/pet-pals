# Internacionalización (i18n) – Preparación futura

Este proyecto aún funciona solo en español, pero ya queda lista la infraestructura para agregar otros idiomas sin tocar gran parte del código.

## Qué se añadió

- Librerías: `i18next` y `react-i18next` (sin forzar `expo-localization`).
- Inicialización en `services/i18n/index.ts` con idioma por defecto `es` y namespace `common`.
- Recursos base en `services/i18n/locales/es/common.json`.
- El arranque de la app importa la inicialización en `App.tsx`.
- Ejemplo de uso en `screens/auth/Ingresar.tsx` (solo cambia la forma de leer strings, no el contenido).

## Cómo usar en componentes

- Con hook:
  ```ts
  import { useTranslation } from 'react-i18next'
  const { t } = useTranslation()
  const title = t('auth.login.title')
  ```
- En props: `label={t('auth.email')}`.

Recomendación: agrega claves por pantalla/feature dentro de `common.json` (p. ej., `auth`, `paseos`, `mascotas`).

## Agregar un nuevo idioma

1. Crea un archivo de recursos, por ejemplo:
   - `services/i18n/locales/en/common.json`.
2. Extiende la inicialización para registrar el nuevo idioma (o importa dinámicamente); ejemplo mínimo:
   ```ts
   import enCommon from './locales/en/common.json'
   i18n.addResourceBundle('en', 'common', enCommon, true, true)
   ```
3. Cambia el idioma en runtime si lo necesitas:
   ```ts
   import { setLanguage } from '@/services/i18n'
   await setLanguage('en')
   ```

> Nota: por ahora `supportedLngs` solo contiene `es`. Cuando agregues otro idioma, recuerda incluirlo.

## Detección del idioma del dispositivo (opcional)

El archivo `services/i18n/index.ts` intenta usar `expo-localization` si está disponible. Si no lo está, la app se mantiene en español. Para activarlo completamente:

- Instala: `npx expo install expo-localization`
- Asegúrate de que la clave `supportedLngs` incluya el/los idiomas que quieras soportar.

## Buenas prácticas

- Claves estables y en minúsculas separadas por puntos: `feature.subfeature.message`.
- Evita concatenar cadenas. Usa interpolación de i18next: `t('greeting', { name })`.
- No bloquees la UI si falta una clave; mantenemos `fallbackLng: 'es'`.

## Mensajes de error y helpers

- Namespace dedicado: `errors` (recursos en `services/i18n/locales/es/errors.json`).
- Helpers disponibles en `services/i18n/index.ts`:
  - `tError(code)`: Traduce un código de dominio (tipo `ErrorCode`).
  - `tErrorMaybe(codeOrMessage, fallback?)`: Si `codeOrMessage` es un código con traducción, la devuelve; si es un string libre, retorna el mismo texto; si es `undefined`, usa el fallback.

Ejemplos:

```ts
import { tError, tErrorMaybe } from '@/services/i18n'

// Código conocido del dominio
const msg1 = tError('NO_AUTENTICADO')

// Respuesta de servicio que puede ser código o mensaje crudo
const res = await AuthService.login(email, password)
const msg2 = res.ok ? undefined : tErrorMaybe(res.error)
```

Notas:

- Los errores de Firebase Auth se mapean a códigos de dominio en `services/firebase/auth.ts` (ver `constants/errors.ts`).
- En pantallas (`Ingresar`, `Registro`, etc.) se recomienda usar `tErrorMaybe` sobre el valor `res.error` para mostrar un mensaje consistente.
